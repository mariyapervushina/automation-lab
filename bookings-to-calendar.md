# Брони → Google Календарь (n8n)

Workflow: `bookings-to-calendar.json`

Читает брони из Google Таблицы и держит в Google Календаре до четырёх событий на каждую бронь: **заезд, выезд, трансфер прилёт, трансфер вылет**. Создаёт новые события, обновляет изменённые, удаляет события отменённых броней. Повторный запуск дублей не создаёт.

## Схема

```
Расписание / ручной запуск
  → Брони (чтение листа)
      ├→ Filter (актуальные брони) → Подготовить события (Set)
      │     ├→ If заезд  ─ true → Заезд: создать → Записать ID заезд
      │     │            └ false → Заезд: обновить
      │     ├→ If выезд  ─ true → Выезд: создать → Записать ID выезд
      │     │            └ false → Выезд: обновить
      │     ├→ Есть прилёт (Filter) → If прилёт → создать / обновить / записать ID
      │     └→ Есть вылет  (Filter) → If вылет  → создать / обновить / записать ID
      └→ Отменённые (Filter) → Удалить заезд → Удалить выезд → Удалить прилёт → Удалить вылет → Очистить ID
```

## Главная идея: ID события хранится в брони

В листе «Брони» четыре скрытых служебных столбца: `ID: заезд`, `ID: выезд`, `ID: прилёт`, `ID: вылет` (AT–AW).

- ID пустой → событие **создаётся**, его ID записывается в строку.
- ID есть → событие **обновляется** по этому ID (новое время, новое название).
- Бронь отменена → события **удаляются**, ID **очищаются**.

Поэтому workflow можно запускать сколько угодно раз: результат один и тот же (идемпотентность).

## Нода «Подготовить события» (Set)

Все даты и названия считаются здесь один раз; календарные ноды только берут готовые поля. Опция **Include Other Input Fields = All** обязательна — иначе If не увидит столбцы ID.

| Поле | Откуда | Время по умолчанию |
|---|---|---|
| `checkin_start / _end / _title` | Дата и время заезда | 14:00 |
| `checkout_start / _end / _title` | Дата и время выезда | 12:00 |
| `arrival_start / _end / _title` | Прилет: дата, время, рейс, аэропорт | 12:00 |
| `departure_start / _end / _title` | Вылет: дата, время, рейс, аэропорт | 12:00 |

- Событие длится 1 час от start.
- Если время не заполнено — ставится время по умолчанию, а в название добавляется «(время не уточнено)».
- Если даты прилёта/вылета нет — `arrival_start` / `departure_start` пустые, и фильтры «Есть прилёт» / «Есть вылет» не пускают бронь в ветку трансфера.

Шаблон расчёта:
```
DateTime.fromFormat($json['Дата заезда'] + ' ' + ($json['Время заезда'] || '14:00'), 'dd.MM.yyyy H:mm').toISO()
```

## Принятые решения и почему

- **Все события со временем, а не «на весь день».** Google Calendar Update дописывает изменения в событие, а не заменяет его. Событие «на весь день» нельзя превратить в событие со временем через Update — Google отвечает `Invalid start time`. Поэтому тип события никогда не меняется, меняется только время.
- **Очистка ID через Clear, а не Update.** Update в Google Sheets пропускает пустые значения и не стирает ячейки. Clear по диапазону `AT{row}:AW{row}` стирает.
- **Удаление с On Error = Continue.** У брони может не быть трансфера (пустой ID) — ошибка удаления не должна останавливать цепочку.
- **В ветке отмены ссылки через `$('Отменённые').item.json`**, а не `$json`: после первой ноды удаления `$json` содержит ответ Google, а не строку брони.
- **Фильтр «Отменённые» требует хотя бы один ID**, иначе уже очищенные отмены обрабатывались бы при каждом запуске.

## Ловушки

- **ё и е.** В таблице `Прилет: дата` (е), но `ID: прилёт` (ё); нода называется «Отменённые» (ё). n8n считает это разными строками. Ошибка «не находит поле / Referenced node doesn't exist» — сначала проверить ё/е. Имена лучше перетаскивать из панели Input, а не печатать.
- **Буквы столбцов в «Очистить ID».** Диапазон `AT:AW` завязан на положение столбцов. Если вставить столбец левее — поправить диапазон.
- **Не переименовывать заголовки таблицы** — на них ссылаются выражения.
- **После копирования нод проверять все поля, особенно выпадающие списки** (столбец в «Записать ID»): их не видно на холсте.
- **Execute step берёт старые входные данные.** После правок в таблице проверять через Execute workflow, иначе ноды «создать» могут наплодить дубли по устаревшим данным.
- **Стёртый вручную ID = событие-сирота.** Если ID удалить из таблицы руками, событие останется в календаре, а workflow создаст новое. Отменять брони только статусом.

## Настройка

1. Импортировать `bookings-to-calendar.json` в n8n.
2. Заменить плейсхолдеры: `YOUR_SPREADSHEET_ID` — ID таблицы, `YOUR_CALENDAR_ID` — ID календаря.
3. Выбрать credentials Google Sheets и Google Calendar (OAuth-приложение в Google Cloud должно быть опубликовано — в режиме Testing токен истекает раз в 7 дней).
4. Часовой пояс n8n: `GENERIC_TIMEZONE=Europe/Istanbul`.
5. Включить workflow (Publish), расписание — каждые 15 минут.

## Проверка после изменений

1. Execute workflow → события создались, ID записались.
2. Execute workflow ещё раз → во всех If `true: 0`, дублей нет.
3. Поменять время у брони → событие сдвинулось, «(время не уточнено)» исчезло.
4. Поставить статус «Отмена брони» → события удалились, ID очистились; следующий запуск — «Отменённые: 0 items».
5. Вернуть статус → события создались заново.
